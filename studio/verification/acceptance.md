## A. Draft → Lua entry → what typing it in real ntex gives

Rules derived from the sources:

- `helpers.parse` reads `<(%d*)(:?)([^<>\n]*)>` as a tab stop only when there
  is a colon or nothing between the brackets. So `<>`, `<3>`, `<:x>`, `<3:x>`
  are tab stops; `<b>`, `< >`, `<1 >` are literal. A default can never hold
  `<`, `>` or a newline, and it is read **raw**: `%` inside a default is not
  doubled (`<:50%>` shows `50%`; `<:50%%>` would show `50%%`).
- `%` followed by a digit, `V` or `%` is special; any other `%` is literal.
- `%<`/`%>` (BRIDGE, landed 22:27): a literal `<` / `>`. Before it landed the
  measured result of `a%<%>b` was the literal text `a%<%>b`; A9–A11 are now
  measured with the escape in place.
- `helpers.nodes` splits trailing whitespace of the last text token off into
  a function node (`trailing_ws`) unless the body has `<0>`. If that
  whitespace contains a newline, LuaSnip raises `[LuaSnip Failed]: { "\n" }`
  (node.lua:590) mid-expansion, and **every later expansion in that Neovim is
  corrupted until restart** (measured: after it, `ff` stops expanding and
  `thm⇥` puts the cursor before the text). See A32/A38 and failure F1.
- Lua drops the first newline of a long string, and `[[…]]` ends at the first
  `]]`; a body that *ends* in `]` cannot be `[[…]]` either (`[[a]]]` is `a`
  followed by a stray `]`, a syntax error). Her own `visual.lua` writes
  `vis("[", "[%V]", …)` for exactly this reason.

C15 (measured, important for "duplicate"): with equal priority the winner
depends on **load order, which differs between live and after restart**.
`inbox.lua` holding `math("xx", [[\chi]])`, `math("pi", [[\varpi]])`: at
startup (files load alphabetically) `xx` → `\chi` (inbox before symbols) and
`pi` → `\pi` (greek before inbox); after a hot reload of inbox.lua, `xx` →
`\times`. So the "Try it" result (zz_studio_try.lua, always last) matches the
live session but not tomorrow's. A duplicate must therefore be a finding with
a priority fix, never a silent save.
