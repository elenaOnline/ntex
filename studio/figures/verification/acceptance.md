# Ntex Figures: acceptance (ADVERSARY)

Written from FIGURES.md, `src/model.rs` (incl. FIG-CORE-B's add-only
`ObjRef::NGonVertex`, `ObjRef::Cayley`, `Scene::cell`), `templates/tex/ntex-base.sty`
and mathematics, **before reading any of figures/src's implementations**.
Machine form: `expected.json`, generated by `gen_expected.py` (cases) and
`groups.py` (group facts). Re-generate: `python3 -IB gen_expected.py`.

Tests: `tests/adversary_parse.rs` (model facts + diagnostics, from
expected.json) and `tests/adversary_build.rs` (Scene invariants, geometry,
groups, TikZ, tectonic, rasters).

## How a case is judged

- **Tiers.** `spec` = FIGURES.md says it. `inferred` = the only sensible
  reading of FIGURES.md (a failure is still a failure, but I say why I read it
  that way). `gap` = FIGURES.md is silent; recorded as what a notes-writer
  expects, reported separately, never counted as a bug by itself.
- **Names and labels** are compared as TeX token lists: whitespace between
  tokens ignored, a single-token group after `^`/`_` equals the bare token
  (`x_{1}` = `x_1`), and these aliases are equal: `\le`=`\leq`, `\ge`=`\geq`,
  `\ne`=`\neq`, `\rightarrow`=`\to`, `\varnothing`=`\emptyset`. A Unicode
  name in a case (`ℤ/nℤ`) matches either the raw token or its LaTeX.
  So `\varphix` (one undefined control word) never equals `\varphi x`.
- **Arrows** are matched as a multiset (order free), with every field in
  model.rs checked against its default unless the case says otherwise — a
  spurious `bend` or `Dashed` fails. `arrows_include` = subset only.
- **Nodes** = `Item::Node` names ∪ arrow endpoints that are not blobs,
  elements, n-gons or Cayley vertices; an implicit node's label is its name.
- **Grid cells** are checked relative to the first listed node (the block's
  origin is not specified).
- **Diagnostics.** `clean` = no Error and no Warning. `error_lines` = an
  Error on each line. `warn_lines` = a Warning on each line (and, with
  `no_errors`, no Error anywhere). `any_lines` = some diagnostic on that line.
  The line is `span.line`; separately (soft) the message should begin
  `line N:` as FIGURES.md shows.

## Derivations

### N-gons (FIGURES.md + model.rs NGon)

- Slot `i` (0-based) sits at angle `90° + 360°·i/n`: counter-clockwise from the
  top. Label `j` starts in slot `j−1`.
- `turn=k` applies `r^k`, `r` = the standard counter-clockwise rotation by
  `360°/n` (FIGURES.md doesn't name the direction; CCW is the convention its
  "counter-clockwise from the top" numbering implies). Label `j` → slot
  `j−1+k (mod n)`.
- Axis code `m` (model.rs: `2k` = through vertex k, `2k+1` = through the
  midpoint of edge k, i.e. between vertices k and k+1) is the line at angle
  `90° + 180°·(m−2)/n`. Reflecting slot `i` across it gives slot
  `(m−2−i) mod n`. Check: `m=2` (vertex 1) sends `i → −i` (fixes the top);
  `m=3` (edge 1.5) swaps slots 0 and 1.
- `flip` applies after `turn`: label `j` → slot `(m−2−(j−1+k)) mod n`.
- **Which axes exist.** For every n there are exactly n reflection axes, at
  angles `90° + 180°·t/n`, t = 0..n−1 (mod 180°):
  - n odd: each axis passes through one vertex and the midpoint of the
    opposite edge (vertex k's axis bisects edge `k+(n−1)/2`). So `k.5` is
    redundant, never new: edge k's perpendicular bisector is vertex
    `k+(n+1)/2`'s axis (n=3: edge 1.5 ↔ vertex 3, code 6).
  - n even: n/2 axes through opposite vertex pairs (vertex k = vertex k+n/2)
    and n/2 through opposite edge midpoints.
  - So `axes` draws n dashed lines, all through the centre, at those angles.
- Worked: square `turn=1 flip=1` (P07): label 1 → slot 3 (right), 2 → slot 2
  (bottom), 3 → slot 1 (left), 4 → slot 0 (top).

### Cayley graphs (groups.py)

Three derivations per group: a concrete model (r^k s^f pairs for Dn, ±1,±i,±j,±k
for Q8, tuples mod n for products, permutations for S3/S4/A4) closed under right
multiplication; my own Todd–Coxeter (HLT with coincidences) for every
presentation, with every relator verified to fix every coset; and sympy's
`FpGroup.order()`. Edges per generator: `|G|` arcs, or `|G|/2` undirected
edges for an involution (drawn once, no head). The build test compares the
implementation's tables to mine as **rooted, generator-labelled graphs**: BFS
from the identity along the same generator must give a consistent bijection,
which proves the same group *with the same generators*, not just the same
order. Element-order statistics are checked too (they distinguish Q8 from D4,
A4 from Z12, S4 from everything of order 24 in this list).

For S3, S4, A4 the generators' meaning is the implementation's choice, so
those check order, element orders, regularity, and edges consistent with the
implementation's own generator orders.

Vertex labels: each label, read as a word in the generators, must evaluate in
the implementation's own tables to that vertex (labels name what they label),
and its length must be the BFS distance (shortlex words are shortest).

## Scene invariants (numerical, adversary_build)

1. Every arrow's path starts within 0.15 cm of its source's box and ends
   within 0.15 cm of its target's box, and neither end lies deep inside a box
   (inset 0.08 cm): arrows end at node boundaries. Blob-to-blob arrows use the
   blob outline's bounding box.
2. Nothing drawn lies outside `scene.bounds` (path points, cubic samples at
   t = ¼, ½, ¾, dots ± r, label centres), tolerance 0.05 cm.
3. No two labels overlap: each label's box is estimated as
   `0.17 cm × visible glyphs` by `0.30 cm` (deliberately small, so a hit is a
   real collision), and boxes may not intersect.
4. Grid nodes sit at `(col·cell.0, −row·cell.1)` relative to the origin; the
   cell is 2.4 × 1.8 cm by default, and `spacing` changes it.
5. Auto-placed nodes are on integer cells; a chain runs left to right on one
   row; a 3-cycle is a non-degenerate triangle; a 4-cycle a 2×2 square; a
   branching a fan (one source, targets in one column or row).
6. Cayley: |G| vertex anchors; total edges = Σ edges per generator; edges
   per colour (blue, maroon, teal, green by generator order) match; an
   involution's edges have no tips. Cyclic: all vertices equidistant from the
   centre. Dn: two concentric rings of n. Zm × Zn: a grid (m distinct of one
   coordinate, n of the other).
7. Blobs: children's outlines inside their parent's bounding box; every
   element dot inside its own blob's outline bounding box and outside its
   child blobs'; top-level blobs left to right in order.

## The look: "it belongs in her notes"

Judged on rasters made headlessly (CoreGraphics `CGPDFDocument` → bitmap →
PNG, via a swiftc script, 4× scale; no viewer is ever opened), next to a
reference `tikz-cd` square typeset with ntex-base.sty.

- **Arrow tips are tikz-cd's** (the `cm` tip that `tikzcd` uses, not TikZ's
  `>` or `stealth`): the TikZ uses the `commutative diagrams` styles or the
  same arrows.meta tips; two heads, tail, hook, `|->` look as in tikz-cd.
- **Labels are Charter** (XCharter text, newtxmath's Charter maths): the PDF
  embeds XCharter / newtx fonts and no Latin Modern / Computer Modern.
  Labels are at `\scriptstyle` for arrow labels like tikz-cd.
- **Palette colours only**: every colour the TikZ names is a palette name
  (or its tint, `name!NN`), mapped by ntex-figure.sty to ntex-base.sty's
  colours. Pixel check: every non-white pixel is (within 14/255) a blend of
  white with one of ntex-base.sty's colours (Ink, the Rule/Back/Head of each
  hue, Slate, Proof greys); ≤ 0.5 % outliers allowed for overlaps.
- **No overlapping labels**, and no label sitting on a line it doesn't
  belong to.
- **Arrows end at node boundaries**, with tikz-cd's small gap, never touching
  or entering a label.
- **Consistent spacing**: rows and columns evenly spaced; the same diagram at
  the same size as the equivalent `tikz-cd` (2.4 × 1.8 cm cells are close to
  tikz-cd's defaults); blobs evenly spaced; Cayley graphs symmetric.
- **Compiles cleanly**: tectonic with `-Z search-path=<temp copy of
  templates/tex>`, no `Missing character` lines in the log (Unicode leaking
  into text mode), no overfull boxes from the standalone border.
